# Building HSMS Proofer for macOS

This document explains how to build a standalone macOS desktop version of **HSMS Proofer** using R, Shinylive, and Electron.

The resulting `.dmg` installer contains an application that runs without requiring users to install R or RStudio. **The current build procedure targets Apple Silicon (ARM64)**; it has not been validated for Intel-based Macs.

## Requirements

- A Mac with an Apple Silicon processor (ARM64).
- R and RStudio (RStudio is convenient but not required).
- The R package `shinyelectron` and its required dependencies.
- The local Node.js/npm installation managed by `shinyelectron`.
- Xcode Command Line Tools.
- A working copy of the HSMS Proofer source directory, including `app.R` and its sourced validation modules.

Before your first build, run in R:

```r
library(shinyelectron)
sitrep_shinyelectron()
```

The project uses the **Shinylive** runtime strategy: R runs inside Electron through WebAssembly rather than through a separately installed R interpreter.

## Build procedure

1. Edit the relevant HSMS Proofer source file (`app.R`, `validator_core.R`, `validator_structure.R`, `validator_editorial.R`, `validator_main.R`, `technical_fixers.R`, etc.).
2. Run the application normally in RStudio and check the intended behavior. Do not package an untested change.
3. Open `build_hsms_proofer_macos.R` in RStudio.
4. Confirm that the two paths near the top match your directories:

   ```r
   app_dir <- path.expand("~/Desktop/HSMS-PROOFER")
   builds_dir <- path.expand("~/Desktop/HSMS-PROOFER-Builds")
   ```

5. Run the complete script using **Source**. Wait for both the initial export and the subsequent Electron rebuild to finish.
6. Read the final message in the R console: it lists the generated `.dmg` path.

The script performs the following operations automatically:

1. Exports the Shiny application to Shinylive and creates an Electron project with `shinyelectron::export()`.
2. Inserts the tested download-window fix into the newly generated `main.js`.
3. Checks the JavaScript syntax and rebuilds Electron for `mac-arm64` with `npm run build-mac-arm64`.
4. Reports the final `.dmg` installer location.

**Do not call `export()` again manually after the script finishes:** this regenerates `main.js` and removes the injected fix until the script applies it again.

## Output files

Each run creates a separate timestamped directory, for example:

```text
~/Desktop/HSMS-PROOFER-Builds/
└── HSMS-PROOFER-20261119-190000/
    ├── shinylive-app/
    └── electron-app/
        ├── main.js
        └── dist/
            └── <generated-installer>.dmg
```

Only the finished `.dmg` is needed for ordinary distribution to end users. The other directories are build artifacts and need not be committed to the source repository. Keep a known-good installer before replacing or removing older builds.

## Why is `main.js` modified?

Shinylive downloads in Electron initially opened an extra blank window. The underlying R reports downloaded successfully, but that auxiliary window remained open after the macOS Save dialog closed.

Two complementary changes are used:

- In `app.R`, a `downloadButton()` compatibility wrapper removes the HTML `download` attribute **only when R is running on the Emscripten/WebAssembly platform**. Conventional Shiny remains unaffected.
- In the generated Electron `main.js`, the build script registers auxiliary windows and closes them when a download completes successfully.

Because `main.js` is generated by `shinyelectron`, **do not maintain a manually edited copy as the source of truth**. Maintain the build script instead. If a future version of `shinyelectron` changes its template, the script intentionally stops when it cannot find the expected insertion point; review and adapt the script before proceeding.

## Test the installer

After building, install the `.dmg` on a test Mac and verify at least:

- HSMS Proofer opens independently of RStudio.
- A known-valid transcription produces the expected clean report.
- A deliberately invalid transcription produces the expected diagnostics.
- Both TSV and TXT reports can be saved with their expected filenames and contents.
- The macOS Save dialog closes after saving, without leaving an empty Electron window.
- macOS warns before overwriting an existing report, when appropriate.

Do not consider a successful compilation alone proof that the packaged application works.

## Troubleshooting and distribution notes

- **`npm: command not found`:** `shinyelectron` manages a local Node.js/npm installation. The R build script locates it and sets `PATH` for the build. There is no need to invoke `npm` directly in Terminal.
- **Warnings about npm dependencies:** do not automatically run `npm audit fix --force`; it can introduce breaking dependency changes. Review reported vulnerabilities before public distribution.
- **Service Worker errors:** Shinylive requires a functioning Chromium Service Worker. A successful `export()` does not guarantee that the app launches. Test the packaged app and examine its runtime logs if startup fails.
- **Unsigned app:** the current build does not configure Apple Developer code signing or notarization. macOS Gatekeeper may warn when other users open a downloaded installer. Code signing, notarization, and security review should be addressed before broad public distribution.
- **Windows:** a separate Windows build procedure is planned. This document describes macOS ARM64 only.

## Repository policy

Commit the R source files, `build_hsms_proofer_macos.R`, and this documentation. Do **not** commit generated `electron-app/`, `node_modules/`, or timestamped build directories. Publish tested installer artifacts separately when ready.
